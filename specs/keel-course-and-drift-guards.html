Purpose

Extract the highest-leverage anti-drift and project-alignment mechanisms from rickflashman/Keel (v2.2.1) and integrate them selectively into our global skill suite—upgrading planf3, full-send, half-send, babysit-pr (plus a one-line caller-context seam in sol-loop), and adding one lightweight complementary skill (project-course)—without adopting Keel's 8-file required documentation standard, version-stamped migration machinery, or human-gated per-change ceremony.

Problem

Our existing delivery suite excels at single-unit execution: planf3 defines one feature or fix in a validated offline HTML spec, finish-line closes one ticket with evidence, sol-loop / council run cross-model review, and full-send / half-send / babysit-pr ship PRs through CI and review bots. Comparing our suite against Keel v2.2.1 surfaces four recurring failure modes that allow drift across sessions and plans:

  • No project-level course anchor or milestone-to-spec link: planf3 only checks AI_DOCS/, APP_DOCS/, and explicit sibling refs; full-send, half-send, and babysit-pr do not check project milestones, non-goals, accepted decisions, or protected paths at all, and ad-hoc sessions have no lightweight pointer telling them where overall project direction lives. A new session can quietly reverse an earlier architectural choice or build off-course.
  • Mechanical holes in planf3 drift enforcement: validate_plan.py --previous protects append-only metadata rows, but does not flag unamended edits or deletions of ac-* acceptance criteria (or rewritten prior amendments), allows a task heading marked [x] while nested verification still reads Not run. or stale text, allows a phase heading marked [x] with unfinished tasks or checklist items, and does not verify that listed existing files exist on disk before build begins.
  • No project-wide drift audit: finish-line verifies one ticket at a time. Nothing checks cross-plan alignment, broken milestone-to-spec links, broken area-map paths, unlinked active specs, or code contradicting accepted project decisions—let alone separating mechanical certainty from code evidence and git inference.
  • Unattended shipping drift & thrash: full-send, half-send, and babysit-pr lack explicit rules against routing around deliberate blockers (protected code paths, production/data boundaries, accepted decision conflicts), lack final-head base-branch checks preventing a PR or rebase from silently redefining its own accepted requirements, lack unified anti-thrash stop caps when the same failure repeats, do not prohibit weakening tests to make a failure disappear, do not pass linked spec/course paths into sol-loop, and do not guard against review-bot suggestions that silently alter accepted requirements or leave linked specs stale.

Solution

Adopt a selective, minimal two-layer design that keeps every repository free of mandatory boilerplate while closing all four drift vectors cleanly:

  1. Harden planf3 mechanically and procedurally: Upgrade validate_plan.py with diagnostic severities (error / warning), unambiguous ok/warnings output, and --strict so repair workflows (build-plan step 1, update-plan step 2, and finish-line step 2) never deadlock on hand-ticked tasks while post-build/shipping verification enforces strict completion. Mechanically enforce ordered append-only #amendments (PF3_AMENDMENT_REWRITTEN) and exact-token ac-* amendment traceability (PF3_AC_MUTATED), warning/strict checks for [x] tasks with a single blank evidence field or placeholder/stale/deferred evidence (PF3_DONE_WITHOUT_EVIDENCE—preserving mixed historical+current evidence like file-pr-haiku-local-review.html and keeping missing/duplicate/non-done blank evidence as structural errors) and premature [x] phases (PF3_PHASE_PREMATURE_DONE), and --repo-root verification of the first path span on existing file rows (PF3_EXISTING_FILE_MISSING—error when all tasks are unstarted [], warning once any task is [wip]/[x]/[f] so resumed builds after file renames/deletes never break). Update planf3 workflows for bidirectional specs/COURSE.md milestone sync (with fixed Planned | Active | Done | Dropped status vocabulary), conditional 1–4 question gap interviews (with no-question-tool fallback), human-owned criteria, deliberate blockers, test integrity, a single local thrash rule (2 consecutive failed fix attempts for the same diagnosed failure), same-task doc sync, and pre-done acceptance re-reads.
  2. Add one focused, opt-in complementary skill — project-course: Owns project-level alignment and read-only drift auditing via one canonical anchor path everywhere (specs/COURSE.md), optionally linked by a 1–2 line pointer in AGENTS.md / CLAUDE.md so even ad-hoc sessions stay on course. Define accepted operationally across every section: governed prose/boundaries (North Star, Non-Goals, Protected Boundaries) are accepted when present in specs/COURSE.md and neither marked Inferred — needs developer review nor inside > PROPOSED; Decision Log rows and linked docs/decisions/ ADRs are accepted ONLY when carrying Status: Accepted (never Superseded by D-NNN); routine milestone bookkeeping (Spec/Status) and factual Area Map updates are explicitly exempt from the approval gate. Backed by a lean, stdlib-only scripts/check_drift.py focused strictly on pure course/plan Certain checks, keeping legacy detection narrow (neither #acceptance nor #coverage AND zero .criterion/.task markers), keeping structural errors fatal on completed modern plans while skipping --repo-root historical file checks, and recognizing retired plans strictly via a standalone semicolon-delimited appended segment of the parsed forward refs cell text starting with Retired: or Superseded by (documented explicitly in update-plan.md and update-course.md, and matching file-pr-haiku-local-review.html's appended superseded by ... segment cleanly without inspecting #amendments or raw HTML).
  3. Factor PR course/spec guard mechanics into a tested stdlib CLI + concise contract reference, and tighten full-send, half-send, babysit-pr, and the compact sol-loop seam: Move all mechanical git, race-free temp-ref fetching (--no-write-fetch-head), ref-pinning & invocation ownership, direct git blob reading (bypassing checkout/smudge filters and rejecting symlinks), validation, course_parser.py constraint/protected-path extraction, narrow blob- and text-bound user-approval recording, and rebase-survival plumbing into a tested Python 3.9+ stdlib script—skills/planf3/scripts/spec_guard.py (with unit tests in skills/planf3/evals/test_spec_guard.py)—exposing seven subcommands (pin, bind-pr, rebase-pin, survival, check --stage pre-commit|pre-push|final, approve, and cleanup), with every post-pin call verifying --guard-prefix + --invocation-id against run-id.txt. This shrinks skills/planf3/references/linked-spec-guard.md to a crisp ≤ 75-line contract focused on CLI invocations and agent judgment calls: (1) resume-before-pre-skip + dual-namespace prior_runs scan + boundary re-evaluation + inline fast-skip trigger reporting guard: n/a when no spec is bound and neither base nor the change touches specs/COURSE.md (while keeping the 1-line test-integrity rule—never weaken, skip, or delete an existing test to make a failure go away—unconditionally inline in full-send Proof [inherited by half-send] and babysit-pr Reviews so it ALWAYS applies even when the guard is skipped); (2) full takeover check when guarded (or before a push that activates the guard, preserving zero-friction waiting on repos that stay guard: n/a), ONE unified server-side CI qualification rule for both takeover and automatic merging (non-queue: trusted always-run merge-candidate guard OR trusted head guard + GitHub strict up-to-date; queue: trusted always-run merge_group guard; absent by default), escalating as an Ask whenever a mandatory merge queue lacks a qualifying merge_group CI guard, and direct head-pinned merges (expectedHeadSha with auto: false / --match-head-commit) with the residual client-side base-tip race documented honestly; (3) unattended approval for accepted criteria, spec deletions, governed COURSE.md/ADR edits or promotions, and code conflicts with fetched target-tip constraints (recording explicit user approval narrowly via spec_guard.py approve bound to exact text or blob OIDs); and (4) snapshot + --previous --strict spec sync. Link concisely from full-send (≤ 150 lines), half-send (≤ 55 lines), babysit-pr (≤ 145 lines), and sol-loop (≤ 154 lines).
  4. Explicitly reject Keel's heavy machinery: No 8-file required doc tree, no recommended/optional doc boilerplate (HANDOFF.md, CHANGELOG.md, USER-GUIDE.md, DESIGN-GUIDE.html, docs/archive/), no tracker headers on every doc, no per-repo generated docs-check scripts or test-results/latest.md scratch files, no risk-class ready-card gate inside unattended shipping skills, no AGENTS.md size lint / secret regex / proposal-age clock / shell-command PATH parsing in check_drift.py, no prescriptive file/function header comment rules, and no keel-init/keel-upgrade version-stamp migration tooling.

Could planf3 simply read AGENTS.md and docs/decisions/ directly without a new skill?   • finish-line (ticket-level closure, untouched): Verifies and closes one specific ticket. Because new status checks in validate_plan.py default to warnings unless --strict is passed, finish-line step 2 never deadlocks on unfinished/hand-ticked specs; finish-line step 4 follows build-plan.md, so it naturally inherits --strict at final closeout (verified zero false warnings on all existing specs).

  • full-send / half-send / babysit-pr / sol-loop (PR delivery): Ship and babysit one PR autonomously while invoking spec_guard.py via linked-spec-guard.md (explicit binding, final-head base checks including linked accepted ADRs, takeover/merge-queue gating, and snapshot --strict sync).
