Purpose

Keep authoring-skills small, portable, and evidence-driven while making its validation and observed-run claims trustworthy. Implement the October 19 review without replacing the skill or widening into unrelated packages.

Problem

Current tooling passes its own tests but can accept invalid YAML, count writes or failed reads as activation, and return success after a failed harness. Guidance also treats local preferences as universal rules, imposes full-review ceremony on narrow requests, and mistakes navigation heuristics for task quality.

Solution

Repair evidence capture first. Then distinguish portable constraints, client behavior, and local policy; introduce proportional Improve modes; align eval guidance and diagnostics. Finish with network-free regression checks and separately approved, controlled behavioral qualification.

Acceptance Criteria

  • Trace. Trace evidence cannot confuse writes, failed reads, unknown results, or a different skill copy with successful activation. Explicit invocation is never reported as proof of automatic discovery.
  • Runner. Runner reports completed, failed, blocked, and timed-out captures truthfully; rejects escaping workspace links; records exact target identity and limitations. No workspace-copy claim implies an enforced security sandbox.
  • Validation. Valid portable YAML and supported optional fields validate; malformed YAML, invalid types, and malformed local eval definitions fail with actionable diagnostics. Advisory wording and size preferences do not masquerade as format errors.
  • Authority. Every constraint is attributable to portable format, named client behavior, or repository policy. Discovery locations and collision behavior are client-specific; local symlink setup is not universalized.
  • Scope. Review-only work makes no edits or model calls by default. Targeted fixes use relevant checks; comprehensive qualification retains repository release gates. Audit delegation is optional and bounded.
  • Evaluation. Guidance separates discovery from execution, uses controlled no-skill or previous-version baselines, tests negative near-misses, protects held-out prompts, and distinguishes iteration coverage from three-profile qualification.
  • Context. Navigation checks accept sufficient section reads and legitimate shared references. Cost output separates metadata, instructions, and static scenario estimates; unrelated bundle growth cannot improve a quality verdict.
  • Alignment. Router, workflows, rubric, templates, compatibility guidance, and current eval assertions agree. Existing case IDs and historical evidence remain intact; six behavioral cases and a labeled trigger dataset cover changed behavior.
  • Qualification. Offline checks pass; approved behavioral runs identify exact revision, provider/model/thinking, fixtures, permissions, invocation mode, and primary evidence. Every missing or blocked check remains visibly unqualified, never a claimed pass.

Non-goals: Replacing authoring-skills with upstream skill-creator; changing other skills; migrating repository eval schemas; building a universal sandbox, eval orchestration platform, or HTML review UI; rewriting historical plans/results; commits, PRs, publishing, or installation changes.

Constraints: Work is scoped to listed files. Preserve unrelated skills/.trash/. Keep existing case IDs, local schema 1, minimum three execution cases, and three release profiles. All implementation status markers start idle. No model calls, dependency downloads, or installed-copy mutation are authorized by this planning request.

Open decisions: No unresolved implementation design blocker. Selected parser: PyYAML 6.0.3 via uv/PEP 723. Live qualification remains approval-gated: exact models, spending/time limits, nested-run count, and demonstrated containment must be supplied before those runs. Missing prerequisites block qualification, not permission to improvise.
