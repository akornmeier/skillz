Purpose

Bring skills/authoring-skills up to the current Anthropic skill-authoring best practices so it is the one place this repository goes to tune and improve an existing skill. The user chose to update the existing skill rather than add a second meta-skill.

Problem

Most of the live guidance is already captured: the condensed reference, the linter's 26 checks, and the 13-dimension rubric cover frontmatter, naming, descriptions, progressive disclosure, feedback loops, content rules, and script hygiene. What is missing is the doc's core procedure for improving a skill that already exists: use it with a fresh instance on real work, watch how that instance navigates the files, bring specific observations back, refine, and test again. The Improve route today is a single static pass. It lints, grades, cuts, redistributes, and reports without ever running the skill. The navigation signals the doc names (unexpected read order, missed references, a file read on every run, a file never read) have no tool that extracts them from a transcript, so the last eval round extracted them by hand.

Solution

Four coordinated edits inside skills/authoring-skills. First, refresh the condensed guidelines so every section of the live doc has a home. Second, add the tuning loop: a new references/tuning-diagnostics.md that owns the Claude A / Claude B cycle, the four navigation signals, and a symptom-to-edit table, plus a rewritten Improve workflow that ends in an observed run rather than a report. Third, make observation mechanical with scripts/trace_skill_use.py, which reads a fresh-session transcript and prints whether the skill fired, which bundled files were read in what order, which reads were partial, and which files were never opened. Fourth, add a rubric dimension for observed behaviour and a linter check for unjustified script constants, update the skill's own evals, and dogfood the loop on one real target before committing.
